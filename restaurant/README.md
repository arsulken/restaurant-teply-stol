# Ресторан «Тёплый стол»

Учебное веб-приложение для заказа блюд на самовывоз. Фронтенд и бэкенд — отдельные проекты, общаются через REST API. Оплата и заказы демонстрационные.

## Быстрый запуск

Нужен Python 3.10 или новее. Первый раз нужен интернет для установки Flask. После установки приложение работает локально без интернета.

1. Распакуйте архив. Из корня скачанного репозитория перейдите в папку исходников: `cd restaurant`. Все следующие команды этого раздела выполняются из папки `restaurant`.
2. Создайте виртуальную среду: `python -m venv .venv` (на macOS/Linux вместо `python` может требоваться `python3`).
3. Активируйте среду:
   - Windows PowerShell: `.venv\Scripts\Activate.ps1`
   - Windows cmd: `.venv\Scripts\activate.bat`
   - macOS/Linux: `source .venv/bin/activate`
4. Установите зависимости: `python -m pip install -r backend/requirements.txt`.
5. В первом терминале запустите API: `python backend/app.py`.
6. Во втором терминале из папки `restaurant` запустите фронтенд: `python -m http.server 8080 --bind 127.0.0.1 --directory frontend`.
7. Откройте http://127.0.0.1:8080 в браузере. Не открывайте index.html двойным щелчком: нужен HTTP-сервер.

Если активация среды в Windows запрещена, используйте `.venv\Scripts\python.exe` вместо `python` для установки зависимостей и запуска бэкенда. Для остановки серверов нажмите Ctrl+C в каждом терминале.

## Демонстрация за 5 минут

1. Как гость просмотрите меню, найдите пасту, проверьте состав.
2. Войдите клиентом. Добавьте блюдо дважды, откройте корзину и оформите заказ.
3. Откройте «Мои заказы». Новый заказ можно отменить — порции вернутся в меню.
4. Оформите ещё один заказ. Выйдите, войдите администратором.
5. В «Управлении» измените состав нового заказа и проведите его через приготовление, готовность и выдачу.
6. Измените цену или остаток блюда. Вернитесь к меню и покажите изменение.
7. Покажите, что администратор тоже может добавлять блюда в корзину и оформлять собственные заказы.

## Проверки

В активированной среде: `python -m unittest discover -s tests -v`.

На подготовленной версии успешно выполнены 24 серверных теста и 12 браузерных проверок. Журналы находятся в `docs/test-results.txt` и `docs/browser-results.json`. Серверные тесты используют временные базы и не изменяют рабочую базу. Для браузерного прогона см. `tests/README.md`: он меняет данные и требует отдельной чистой демонстрационной базы.

## Архитектура и правила

- `frontend/`: HTML, CSS, JavaScript, отдельный статический сервер на 8080.
- `backend/`: Flask и SQLite, REST API на 8000.
- `docs/`: API, схемы, доска задач, изображения экранов, фактические проверки.
- `tests/`: серверные тесты и повторяемый браузерный сценарий.
- `backend/restaurant.db`: создаётся автоматически, не входит в архив.

Корзина не резервирует порции. Заказ проверяет остатки повторно. Все цены API указаны в копейках. Новый заказ можно отменить один раз. После начала приготовления клиентская отмена запрещена. Администратор редактирует состав только нового заказа с пересчётом по текущим ценам. Переходы: new → cooking → ready → completed; new → cancelled.

## Настройка

Адрес API задаётся в `frontend/config.js`. Путь базы меняется переменной окружения `RESTAURANT_DB`; порт API — `PORT`. Разрешённые браузерные источники перечислены в `backend/app.py`: localhost:8080 и 127.0.0.1:8080. При смене портов согласуйте обе стороны.

Для сброса демо остановите бэкенд, сохраните нужные данные и удалите только `backend/restaurant.db`, затем запустите снова. Эта операция удалит локальные аккаунты, корзины и заказы.
