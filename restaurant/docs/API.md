# REST API ресторана

База: http://127.0.0.1:8000/api. JSON в UTF-8. Цены и итоги — копейки, quantity и stock — целые числа.

## Авторизация

POST /auth/register — `{ "name":"Иван", "email":"ivan@example.test", "password":"Password1" }`. Имя 2–60, email до 120, пароль 8–128 символов. Роль всегда client. Возвращает 201 и `{ "token":"…", "user": { "id":3, "name":"Иван", "email":"ivan@example.test", "role":"client" } }`.

POST /auth/login — `{ "email":"client@restaurant.test", "password":"Client123!" }`. Возвращает 200 и token/user. Сессия 8 часов.

GET /auth/me — профиль. POST /auth/logout — удаляет текущий токен, 204.

Защищённые запросы: `Authorization: Bearer <token>`. Для JSON-тела: `Content-Type: application/json`.

## Меню

GET /health — `{ "status":"ok" }`.

GET /dishes — массив объектов `{ "id":1, "name":"Брускетта с томатами", "category":"Закуски", "description":"…", "price":29000, "stock":20 }`. Доступ без авторизации.

## Корзина и заказы клиента

GET /cart — `{ "items":[{ "id":1, "name":"…", "category":"…", "description":"…", "price":29000, "stock":20, "quantity":2 }], "total":58000 }`.

PUT /cart/1 — `{ "quantity":2 }`. Задаёт абсолютное количество 1–99, возвращает обновлённую корзину. Проверяется остаток. DELETE /cart/1 — удаляет позицию, 204.

POST /orders — `{ "comment":"Положите приборы" }`, комментарий до 300 символов, по умолчанию пустой. 201 и объект заказа. Тело клиента не задаёт итог, цену или статус. Корзина не резервирует порции, повторная проверка выполняется здесь.

GET /orders — массив собственных заказов. Структура: `{ "id":1, "user_id":2, "status":"new", "total":58000, "created_at":"2026-09-23T10:00:00+00:00", "comment":"", "items":[{ "id":1, "order_id":1, "dish_id":1, "name":"Брускетта с томатами", "price":29000, "quantity":2 }] }`. Дата в примере иллюстративная.

POST /orders/1/cancel — `{}`. Только собственный new, 200 `{ "ok":true }`. Возвращает порции. Повторная отмена 409. Чужой или отсутствующий заказ — 404.

## Администратор

Администратор также имеет все клиентские маршруты.

GET /admin/orders — все заказы с дополнительным полем customer (имя клиента).

POST /admin/dishes — `{ "name":"Чай", "category":"Напитки", "description":"Чёрный чай", "price":15000, "stock":8 }`. 201 `{ "id":9 }`.

PUT /admin/dishes/9 — тот же полный набор полей. 200 `{ "ok":true }`. Название 2–80, категория 2–40, описание 2–500 символов. Цена 1–10000000 копеек, остаток 0–10000. Блюдо не удаляется: для снятия с продажи задайте stock=0.

PATCH /admin/orders/1/status — `{ "status":"cooking" }`. Переходы только new→cooking, new→cancelled, cooking→ready, ready→completed. Недопустимый переход 409.

PUT /admin/orders/1/items — `{ "items":[{ "dish_id":1, "quantity":2 }, { "dish_id":8, "quantity":1 }] }`. Полностью заменяет состав только нового заказа. От 1 до 50 уникальных блюд, количества 1–99. Прежние порции возвращаются, новые резервируются, цены берутся из текущего меню. Ошибка любой строки откатывает всю операцию. 200 `{ "ok":true }`.

## Ошибки и границы

`{ "error":"Текст ошибки" }`: 400 — формат и диапазоны, 401 — вход, 403 — права, 404 — отсутствующий/недоступный ресурс, 409 — конфликт. Успешное удаление/выход 204 не содержит JSON. Тело запроса ограничено 32 КиБ. OPTIONS используется для CORS.

Поиск и фильтрация категорий выполняются на фронтенде над небольшим меню. Пагинация, оплата, email-уведомления, аудит и лимит попыток входа не реализованы. Проект рассчитан на локальную учебную демонстрацию.
